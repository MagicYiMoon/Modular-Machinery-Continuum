# Botania 火花魔力仓

MMC 1.3.0 新增。需要 Forge 1.20.1 的 Botania 1.20.1-456-FORGE，以及其必需前置 Patchouli、Curios；服务器和客户端均须安装。本模组不内嵌 Botania。

## 放入结构

| 方向 | 方块 ID | 用途 |
| --- | --- | --- |
| 输入 | `modularmachinery:blocksparkmanainput` | 从附近魔力池请求魔力，供机器配方消耗 |
| 输出 | `modularmachinery:blocksparkmanaoutput` | 保存配方产出的魔力，供原生火花网络抽取 |

两者容量固定为 **1,000,000 魔力**，不使用旧魔力接口的 `Mana Capacity` 配置。原有 `modularmagic:blockmanaproviderinput`／`blockmanaprovideroutput` 的 ID、配置和默认 100,000 容量不变。

机器结构必须明确允许新方块，可用选区工具导出，或修改结构 JSON，例如：

```json
{"x":1,"y":0,"z":0,"elements":"modularmachinery:blocksparkmanainput","selector-tag":"mana_in"}
```

它们不会自动替换已有结构中的旧接口。生存合成为：顶部 Botania 火花，中间对应方向的旧魔力接口，两侧红石，底部紫水晶碎片。石镐或更高级镐可挖掘掉落；拆除不保留内部魔力。未安装 Botania 时只有占位方块，无功能方块实体，也不加载这两个合成配方。

## 连接火花

将 Botania 原生火花放在仓室顶部，同一仓室只允许一个。使用 Botania 原生染料、升级与森林法杖操作火花。

输入示例：在有魔力的普通魔力池顶部放火花，在输入仓顶部也放火花，两者保持同色并位于原生火花搜索范围内。输入仓每 **10 tick** 尝试建立连接，实际搬运交给 Botania。456 版原生搜索采用各轴扩展 **12 格的包围盒**，基础连接速率为 **1000 魔力／tick**，多连接时分配和实际总速率由 Botania 决定，不是 MMC 额外保证的总吞吐量。满仓停止请求，腾出空间后重新请求。

输出有两种常用连接方式：

1. 输出仓使用普通火花，接收魔力池使用 **DOMINANT（主导）** 火花。
2. 输出仓使用 **RECESSIVE（衰弱）** 火花，接收魔力池使用普通火花。

两个普通魔力池火花不会自行互传；输出仓同样遵守这一规则。染色须一致，隔离火花不参与输入仓主动请求。其他升级仍按 Botania 原生规则工作，例如扩散升级可能消耗仓内魔力给玩家物品充能；不要将输入／输出配方方向理解为禁用所有火花升级行为。

输出仓拒绝外部正向灌入魔力，只允许配方写入及原生网络抽出。为避免主导火花从其他池吸入后丢失魔力，它向外部报告“不能继续接收／已满”；这不是仓内实际储量。机器配方仍使用实际剩余容量判断能否输出。旧 gugu 的专用发射器绑定逻辑未移植，本文不保证该附加行为。

## 配方

沿用现有 `modularmachinery:mana`，不新增配方资源类型：

```json
{
  "machine":"your_machine",
  "registryName":"spark_mana_recipe",
  "recipeTime":100,
  "requirements":[
    {"type":"modularmachinery:mana","io-type":"input","amount":1000,"selector-tag":"mana_in"},
    {"type":"modularmachinery:mana","io-type":"output","amount":10,"perTick":true}
  ]
}
```

`perTick` 缺省为 false，输入开工扣一次、输出完工产一次；true 为每个工作 tick。支持现有 CraftTweaker 魔力需求、普通／工厂控制器、选择器与批量倍率。输出已满时预检阻止支付同组输入，不会通过输出仓的外部“已满”信号错误判断配方空间。同一种配方最多占用一个工厂线程的规则不变。

空手右击可查看魔力量，森林法杖右击同步数值并提示；持法杖瞄准时提供 Botania 原生魔力 HUD。储量随区块保存，读取时限制在 0～1,000,000；拆除后新方块不会继承原储量。

服务端验证及客户端限制见[功能范围与测试说明](../TESTING.md)与 [功能范围与测试说明](../TESTING.md)。


## 可视化编辑魔力需求

安装 Botania 后，管理员执行 `/modularmachinery gui`，选择机器和普通 JSON 配方，在输入或输出框点击 `+` →“魔法资源”。选择“Botania 魔力”，填写 `0～2147483647` 的整数用量。单次以 Mana 计量：输入开工扣除、输出完工添加；切换“逐 tick”后以 Mana/t 计量，在每个成功推进的加工 tick 输入／输出。没有概率设置。

普通魔力接口和火花魔力仓都使用同一个需求类型，不在配方中按仓型拆分。通过已有接口分组选择对应结构部件。缺魔力或输出空间不足时沿用已有等待／暂停与取消策略；批量倍率通常放大用量，已有批量豁免不会被用量编辑覆盖。保存后选中该需求，点击“批量设置”，可选择随批量放大、整批一份或恢复默认。

点击已有魔力需求可修改用量和单次／逐 tick 开关，不能在原位置改变输入输出或资源家族。保存等待服务器确认，失败保留草稿；取消未提交修改不写文件。未安装 Botania 时隐藏魔力选项，脚本和适配器来源仍只读。此面板自 1.3.0 提供，详见[功能范围与测试说明](../TESTING.md)与 [功能范围与测试说明](../TESTING.md)。
