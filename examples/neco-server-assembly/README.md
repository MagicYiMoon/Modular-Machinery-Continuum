# 新式服务器装配参数示例（开发中）

**状态更新（2026-11-14）：对新星工程的核查仅发现新式服务器及组件的注册／资源预留，未发现对应的生存配方、任务、多方块定义或实际算力接线。装配器及新式服务器仍未接入；本目录保留为已有后端的格式示例，不代表计划继续提供玩家装配入口。详见[范围核查](../../docs/NECO_GUIDE_ZH.md)。**

这一组配置服务于NECO新式模块化服务器装配后端，与已有HyperNet升级总线CPU/GPU/RAM配置分开。当前已可读取和重载模块定义，并在服务端生成装配检查与参数预览；**装配器方块、服务器物品、玩家装配界面和正式网络运行仍未接入**。复制这些文件不会让旧处理器自动使用新式模块，也不会新增配方或创造物品。循环研究仍为占位。

## 放置位置与更新

将`modules/`中的JSON放到服务端`config/modularmachinery/server_modules/`；允许子目录。服务器启动和机器定义重载（含`/reload`）读取整批定义，不需要为了改这里的参数重新注册物品或重启。此阶段不向客户端发送全部模块配置，后续装配器只应同步当前窗口所需的数据。请勿把本节误用于尚未解决的动态方块注册项同步问题。

每文件一个对象，示例使用原版物品便于检查配置格式；不是模组自带的生存获取方式。正式整合包可将`item`换成已存在的模组物品ID。配置不会创建物品、材质或获取配方。新星工程的结构、模块表和数值未搬入；这里的数值仅为示例。

## 通用字段

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一的模块定义ID，必须带命名空间，如`example:cpu` |
| `item` | 实体物品ID，必须带命名空间，如`minecraft:redstone` |
| `type` | 下表的模块类型 |
| `display-info` | 可选的显示阶数和说明，沿用现有`tier`、`tooltips`格式；不限制能力 |

一个物品ID只能绑定一种模块，重复ID或重复物品绑定会拒绝整批目录。与源版物品匹配规则一致，匹配不依据数量、附魔、自定义名称或NBT；不要用同一物品的不同NBT来声明多种模块。物品自带的generation、bandwidth等数字不会成为能力参数。缺失的物品ID可以保留在配置中，但不会回退为空气或给其它物品授予能力。

## 类型与参数

| type | 物理槽位 | 必填参数 |
| --- | --- | --- |
| `cpu` | CPU | `generation`、`energy-ratio`、`bandwidth` |
| `gpu` / `soul_card` / `quantum_card` | 计算卡 | 同CPU |
| `ram` | RAM | `bandwidth`（提供的硬件带宽） |
| `cpu_extension` | CPU扩展 | `bandwidth`（源版字段；有效消耗仍为0，见下文） |
| `calculate_extension` | 计算卡扩展 | `bandwidth`（消耗） |
| `extension_extension` | 扩展卡扩展 | `bandwidth`（消耗） |
| `cpu_heatsink` / `ram_heatsink` / `calculate_heatsink` / `extension_heatsink` | 对应散热槽 | 无数值参数 |
| `psu` | 电源 | `energy-provision`（最大供能，FE/t） |
| `capacitor` | 电容 | `energy-capacity`（FE）、`energy-consumption`（最大放电，FE/t） |

`generation`为正有限数，`energy-ratio`为非负有限数；`bandwidth`为0..2147483647的整数，电源/电容参数为0..9223372036854775807的整数。不适用于当前类型的参数、拼错字段、数字字符串及应为整数的小数均拒绝，避免“保存成功但没有作用”。

原`ModuleCPUExt`保留带宽字段，但`getHardwareBandwidth()`实际返回0，本移植预览也按0计费；没有悄悄改成新规则。源版扩展功能卡基类是抽象类，未发现可实例化的具体实现，所以`extension_card`仍不支持；不额外发明扩展效果。铜管虽有模块类，但没有对应可装配槽，此处不提供铜管类型。

## 四类算力与检查

下表为源版固定类型效率，输出为`generation × 类型效率 × 带宽效率`；多个有效计算模块相加。此处是装配器模拟值，不代表服务器已开机或已经交付算力。

| 模块 | intricate（复杂计算） | logic（密集运算） | neuron（神经网络规模） | qbit（量子位） |
| --- | ---: | ---: | ---: | ---: |
| CPU | 1 | 1 | 0.025 | 0.001 |
| GPU | 0.2 | 5 | 0.1 | 0.005 |
| 灵魂计算卡 | 0.01 | 0.005 | 1 | 0.0001 |
| 量子计算卡 | 0.5 | 0.25 | 0.3 | 1 |

RAM提供带宽，计算模块及对应扩展消耗带宽。源版带宽效率使用float比值，限制为50%..100%；没有提供带宽时固定0。带宽消耗超过提供量的150%时装配报错。例如提供8、消耗12时仍可通过带宽检查，效率约66.67%；消耗13则报错，不显示预计算力。

检查至少有CPU、RAM、PSU、电容，扩展依赖和各自散热器齐全；缺少时列出诊断，不显示预计产出。模块的“存在”检查沿用源版，不能把带有零参数的PSU、电容或RAM当作实际可供给资源的设备。缺失定义、错误类型或未知物品占槽也会报错，物品数据保留以便恢复。功率/容量汇总使用任意精度整数防止long溢出；浮点产出汇总超出范围时报错，不展示无穷值。

`energy-ratio`保留源参数，模拟预览不消耗FE，不根据PSU或电容参数再裁剪预计算力。散热器按物理单槽一件计，不新增热量、维修或冷却消耗。新式服务器正式运行链路尚未实现，不能拿这里的预览替代现有旧式HyperNet实际供给与结算。

## 配置错误与边界

一个文件最多16KiB、目录最多1024文件、总文本最多4MiB、JSON嵌套最多16层，重复键或尾随第二个对象拒绝。无效UTF-8、损坏文件、越出配置目录的文件链接也拒绝。整批解析成功后一次替换目录；失败清空可用定义并显式标记目录无效，避免保留旧能力继续使用。原文件及已装配服务器物品不改写；修复后重载即可恢复参数。未来装配窗口须在目录身份变更时关闭，不能继续提交旧窗口动作。
